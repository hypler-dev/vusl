# Extraction provenance

VUSL began as the RUSL design in [Rangoon](https://github.com/hypler-dev/rangoon/tree/d23b2b73e7d0436325a03264144ac87c0056c10b). This repository separates specification ownership from the consuming application. The initial extraction includes the October 18, 2026 VUSL naming edits and link/ownership corrections; it is not a byte-identical copy of the earlier Markdown.

[The manifest](conformance/manifest.json) records original source paths and SHA-256 identities at the pinned Rangoon commit, alongside destination paths and initial-extraction hashes. Source paths retain the original `docs/rusl.md` and `docs/rusl-conformance.md` names. Destination Markdown was edited during extraction and is not asserted to exist in the source commit. All three JSON vector files are byte-identical to the pinned Rangoon base. Their historical `rusl` filenames, language/profile tokens, digest domain and acceptance IDs remain unchanged. Changing those values is a behavioral migration, not branding.

The initial VUSL extraction is preserved at commit `b55e01955e9c59cd6ab652afe9a54c43589b09b8`. The manifest's `sha256` values identify destination bytes in that snapshot; `sourceSha256` identifies the stated Rangoon source bytes. Later editorial revisions do not rewrite either historical identity. The working manifest must remain byte-identical to the extraction manifest. A future behavioral migration needs its own reviewed revision record rather than replacement of this extraction evidence.

The resolution of [repository-coordination PR #1](https://github.com/hypler-dev/vusl/pull/1), inspected at `fc12d79560202be94610b49d40f49ef4f4d652a4`, retains its ownership guidance but supersedes its proposed current-file-hash manifest model. Do not apply that branch's `conformance/manifest.json` changes or its corresponding mutable-hash prose. Reviewed editorial revisions are identified by their own commits and evidence; the initial extraction manifest is never their current-file ledger. The reviewed branch carries this resolution under the separate publication authorization. PR #1 records its exact remote head and publication receipt; a branch update does not merge the PR or release a profile. The [current work record](docs/implementation-plan.md#repository-integrity-and-candidate-construction--october-19-2026) owns integration status.

Run `python3 scripts/validate.py` in a Git checkout containing that local extraction commit. The validator uses local Git objects with replacement objects and transport access disabled to verify the extraction manifest and all seven historical destination hashes. It separately checks that all seven current paths exist, the three current JSON vector files still match their preserved hashes, and current Markdown links, whitespace and PNG identity pass. Current Markdown need not match its initial-extraction hash. The validator does not retrieve history or verify Rangoon source bytes against a remote repository; the source hashes remain recorded provenance. If Git or the extraction commit is unavailable, validation fails explicitly. A source archive alone cannot complete this historical check.

The experimental Rust parser and Python reference remain in Rangoon. At extraction, the locked/offline D1 Rust suite passed eight tests and the Python reference passed fourteen tests. Those results cover the existing offline subset, not provider integration, deployment readback, semantic-equivalence detection, authorization, verified effects or this repository's broader architecture families. Current source is linked by immutable commit; subsequent code changes need their own evidence.

The logo in `assets/vusl-logo.png` was generated for this project with OpenAI image generation and selected on October 18, 2026. It is a raster PNG on a light background, not an authored vector asset. No uniqueness or trademark clearance is asserted.

No private strategic assessment, credentials, native test logs, customer data, application database or engine runtime is included in this extraction.
